# County research files

National datasets stop at the county line. What homelessness looks like in a given county lives
in local reports, audits, plans, budgets and news, and a person has to find and read those. Each
county gets one human-written file here, and a machine re-checks every link, number and phone
number in it on every run.

Layout: `research/county/<ST>/<5-digit FIPS>-<slug>.md`, for example `research/county/PA/42049-erie.md`.
`CHECK.md` in this folder is generated by the maintainers' ingest run: it shows link health,
claim checks and contact checks for every county file. Do not edit it or include it in a pull
request.

## How to add a county

1. Start the file: `python3 scripts/county.py new <FIPS>` writes `research/county/<ST>/<FIPS>-<slug>.md`
   from `TEMPLATE.md`, prefilled with the county's CoC, housing authorities and officials. Quote
   the FIPS (`"01001"`) if you copy the template by hand.
2. Fill `sources` with every document you cite. For numbers you want on the county page, add a
   `claims` entry with a short `quote` copied exactly from the document. The value must appear
   in the document too.
3. Optionally fill `responsible` (the public offices that answer for each figure) and `help`
   (service lines for printable flyers), each with the official page that publishes the details.
4. Write the narrative under the template headings. Every sentence cites a source.
5. Run the checker and read what it says. It needs no database:
   ```bash
   python3 scripts/county.py check <FIPS>
   ```
   Fix every claim, phone or email it could not verify, and every problem it lists in the file.
6. Open one pull request per county, with that one file: `python3 scripts/county.py pr <FIPS>`
   (add `--dry-run` first to read what it will do). Paste the check output into the pull request.

## Rules

- **Public sources only.** Anything you cite must be readable by anyone without an account.
- **No individuals experiencing homelessness are named or pictured.** Not in the text, not in a
  quote, not in a linked photo caption you repeat. Write about groups and programs.
- **Every number is cited**, and a number in `claims` carries an exact `quote` from the document.
  The checker only publishes a claim when the quote and the value are both found in the text.
- **Quotes are exact.** Copy them; do not paraphrase inside quotation marks. Curly versus straight
  quotes, dashes and thousands separators are normalised for you.
- **Contact details are official office details only**, exactly as an official or the office
  publishes them on the page you cite: office phone lines, office email addresses, office street
  addresses. Never personal cell numbers, home addresses or personal social media accounts.
  Naming an official is fine when the role is public and the name is published with it.
- **Help lines are organizations' published service lines only**: what the provider itself lists
  on its own page (main line, intake line, hours, address). No staff members' direct numbers.
- **Paywalled articles**: cite a free syndicated copy instead, such as the publisher's own
  Yahoo News or MSN syndication of the same story. The checker never reads around a paywall and
  never uses an archive copy of a paywalled article.

## What the checker does

`ingest/domains/local_sources.py` reads every county file, validates the front matter (bad
entries are reported and skipped, never fatal), fetches each source, and:

- extracts the text (HTML via the standard library; PDF via `pdftotext` when installed, else the
  source is marked `text_unavailable`). The page title, meta description and the JSON-LD
  article text a publisher declares count as the document's text.
- marks each claim `verified`, `quote_missing`, `value_missing` or `unverifiable`; only verified
  claims become `metric` rows (`entity_type='county'`, metric `local_<name>`). A claim that was
  verified before and fails now keeps its metric row; `CHECK.md` shows the failure.
- checks each `responsible` and `help` entry's name, phone (compared as digits), email and
  address (street number plus street name) against the live page cited for it. Contact details
  are never verified from an archive copy: a phone number on a street flyer has to be current.
- writes one `doc` row per source and the tables `local_sources_check`, `local_sources_claim`,
  `local_sources_responsible` and `local_sources_help`, then regenerates `CHECK.md`.

## How the scraper gets documents

Local government and news sites often refuse scripts, sit behind bot challenges, or move
articles when they change publishing systems. The checker climbs a ladder
(`ingest/fetch_ladder.py`) and stops at the first rung that returns a real document, meaning an
HTTP 200 that is not a challenge page, a paywall stub or a near-empty shell:

1. `direct`: our own user agent, redirects followed.
2. `retry`: only after a 429 or 503; honours `Retry-After` (capped at 120 s) and backs off.
3. `browser_headers`: a desktop Chrome user agent with normal browser headers in a session that
   keeps the site's cookies.
4. `alternate`: forms the publisher itself serves: AMP pages, the WordPress REST API, the
   site's RSS or Atom item for this URL, a linked PDF version.
5. `wayback`: the Internet Archive's closest good capture, fetched as the original bytes.
6. `wayback_fresh`: when no capture exists, ask the Internet Archive to save one (at most one
   request every 10 s and 20 per run), then read it. Skipped for pages the publisher says are gone.
7. `render`: a headless browser (`ATLAS_BROWSERLESS_URL` for a Browserless endpoint, or local
   Playwright) for pages that only exist after JavaScript runs. Without either it is recorded as
   `skipped (no renderer)`.

Each source's status is `ok` (a live rung), `archived` (a Wayback copy, dated), `paywalled`,
`blocked` (every rung failed on a refusal or challenge), `gone` (404 or 410 and no archive copy),
`robots_disallowed` (robots.txt forbids us and the archive has no copy), `text_unavailable` or
`error`. `CHECK.md` lists every rung tried for every source, so "Wayback copy, 2025-07-23" next
to a citation tells you exactly why.

Hard limits. These are not settings:

- Never submit a login form or send credentials of any kind.
- Never solve a CAPTCHA or send one to a solving service. An interactive challenge ends the
  render rung.
- Never bypass a paywall. A paywall stub moves the ladder to the next live rung; an archive copy
  of a paywalled article is not used and the source is marked `paywalled`.
- robots.txt is honoured for our own requests. When it disallows our user agent, rungs 1 to 4
  and 7 are skipped for that host and only the archive is read (the archive did the fetching,
  not us); the attempts list records `robots disallowed`.
- One request per second per host, never more than three tries per rung.
